# protean documentation

Two kinds of file live in this directory, and mixing them up wastes your time.

**Documentation** tells you how to use protean today.
**Engineering records** are plan documents written while building a piece of
work and corrected in place afterwards. They are kept because on this project
the diagnosis that looked obvious has been wrong often enough that the wrong
turns are the useful half — but they describe decisions and dead ends, not the
current tool surface, and several describe work that was dropped.

### How the figures are made

Every image under `images/` is produced by
[`figures/make_figures.py`](figures/make_figures.py), which drives a real
headless browser through the same tool calls the documentation prints beside
each picture:

```bash
npm run build --prefix viewer
uv run python docs/figures/make_figures.py            # all of them
uv run python docs/figures/make_figures.py --only presets views
uv run python docs/figures/make_figures.py --list
```

Generated rather than collected, because a picture in the README is a claim
about what protean does *now*, and hand-collected screenshots go stale silently
— which is the one failure mode this project spends most of its effort on.
Every capture is checked for ink before it is written, so a blank frame fails
the run instead of quietly composing an empty tile.

`tools.md` and the README's tool table are generated by
[`generate/tool_reference.py`](generate/tool_reference.py), and
`tests/test_docs_generated.py` fails if either drifts.

## Engineering records

Not documentation. Written while building, corrected in place, and kept as a
record. `CONTRIBUTING.md` describes the practice: *"a plan document per
substantial piece of work, corrected in place afterwards… If you fix something
these documents describe wrongly, fix the document in the same PR."*

| File | What it records |
|---|---|
| [backlog.md](backlog.md) | What a 499-probe corpus and the benchmark turned up, what was fixed, what is still **open**. The most useful of these. |
| [views.md](views.md) | The plan behind the one-call views and the viewer-side switcher. §5.1 and §4 shipped; §5.2 onward did not. |
| [cryoem.md](cryoem.md) | The volume and map work, including the contour-unit rule it initially got backwards |
| [alternate-conformers.md](alternate-conformers.md) | Why `alt` behaves as it does, and why analysis resolves one state |
| [symmetry-handles.md](symmetry-handles.md) | Assemblies, `sym N`, and what a copy means |
| [session-state.md](session-state.md) | What a session file holds and what it deliberately does not |
| [ci-and-tests.md](ci-and-tests.md) | The CI design and what each gate is for |
| [soft-matter-plan.md](soft-matter-plan.md) | The plan behind `boil`, the print finishes and the phosphor trails |
| [soft-matter-status.md](soft-matter-status.md) | Where that work actually stands. Kept current deliberately |
